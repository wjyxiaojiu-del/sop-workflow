# SOP 工作流

一个面向个人的本地桌面 SOP（标准操作流程）工具：把重复工作整理为模板，启动独立执行记录，按步骤完成，暂停后继续，并保留历史。

## 功能特性

- **模板管理**：新建、编辑、删除、复制；科研 / 学习 / 开发 / 生活 / 其他分类，标签、收藏和最近使用排序。
- **全文搜索**：匹配模板名称、描述、标签、步骤标题、步骤备注及子步骤内容。
- **执行清单与流程图**：顶层步骤、子步骤均可勾选；同一套进度计算用于首页、执行页和历史记录。
- **变量与快照**：在步骤标题、备注和子步骤中使用 `{{变量名}}`；开始时填写。已启动的执行记录保留独立快照，后续修改或删除模板不改变它。
- **执行状态**：执行中、暂停、完成、放弃。关闭应用后保留进度；暂停期间不累计执行耗时，完成和放弃都有历史记录。
- **本地数据保护**：兼容旧版数据，临时文件写入后替换主文件；保留最近 3 份写入前备份，主文件损坏时尝试最近的有效备份。
- **JSON 导入 / 导出**：包含模板、执行记录、历史和版本信息；导入可合并或替换，确认保存时先备份已有数据。
- **桌面交互**：快捷键、未保存关闭确认、窗口大小和最大化状态恢复、非阻塞提示。

无需账号或云服务，不包含多人协作、云同步、AI 生成或模板市场。

## 使用方式

### Windows 本地构建产物

本轮版本为 **1.1.0，Windows x64**。如果你在本地完成了打包，可以运行：

- [便携包](<dist/SOP工作流 1.1.0.exe>)：双击直接启动，不需要另行安装 Node.js 或 Electron。
- [安装包](<dist/SOP工作流 Setup 1.1.0.exe>)：NSIS 安装向导，可选择安装目录。

本地 `dist/` 中的链接指向被 Git 忽略的构建输出；正式分发通过 GitHub Release v1.1.0 提供（2026-10-24 发布，含安装包与便携包及 SHA-256 校验值）。本次产物未代码签名，Windows 可能显示未知发布者 / SmartScreen 提示；请仅运行来源可信且校验一致的文件。安装包已于 2026-10-24 实测：NSIS 静默安装（per-user，默认目录 `%LOCALAPPDATA%\Programs\sop-workflow`）→ 安装版启动 → 静默卸载，安装目录、HKCU 卸载项、桌面与开始菜单快捷方式全部清理干净；便携包已从项目目录外独立启动并验证重启持久化。注意从 Git Bash 直接执行安装包会段错误，请用资源管理器双击或 PowerShell `Start-Process` 运行。

### 从源码运行

使用支持 `node:test` 的 Node.js 和 npm。本次本机验收使用 Node.js 24.18.0；CI 配置覆盖 Node.js 18 / 20 / 22，已随 2026-10-24 推送在远程全部通过。

```powershell
npm install
npm test
npm start
```

日常开发保留锁文件；需要按锁文件重新安装时使用 `npm ci`。

如果某些 IDE / 自动化宿主设置了 `ELECTRON_RUN_AS_NODE=1`，Electron 会误以 Node 模式启动。先在当前终端清除该变量：

```powershell
Remove-Item Env:ELECTRON_RUN_AS_NODE -ErrorAction SilentlyContinue
npm start
```

宿主仍向子进程注入该变量时，使用 [构建与排障说明](<docs/BUILD-AND-VALIDATION.md>) 中的显式子进程环境方案。

### 打包为可执行文件

```powershell
npm run build
# 或只打便携包
npm run build:portable
```

打包器为 `electron-builder`，不是旧文档中的 `electron-packager`。输出位于 `dist/`。本次受 GitHub 下载连接及 Windows 符号链接权限影响，采用已安装的 Electron 运行时和未签名配置完成构建：

```powershell

```

网络、镜像和权限的具体处理，以及产物校验值，见 [构建与排障说明](<docs/BUILD-AND-VALIDATION.md>) 和 [验收报告](<docs/V1.1-VALIDATION-REPORT.md>)。关闭签名与资源编辑并非正式发布建议。

## 快速上手

1. 点击 **新建模板**，填写名称、描述、分类与标签，可设为收藏。
2. 添加步骤和子步骤；用上下移动按钮调整顺序。删除步骤前会确认。
3. 在步骤标题、备注或子步骤中写入 `{{论文}}` 这类变量。
4. 保存模板，进入详情；可以复制模板继续编辑，或点击 **开始执行**。
5. 填写变量，在清单或流程图中勾选任务，记录执行备注。
6. 中途点击 **暂停**；重新打开应用后，从首页或执行中列表继续。
7. 点击 **完成** 或 **放弃** 后，到历史记录查看结果、完成率和累计耗时。未全部勾选也可确认结束，完成率保留实际值。

### 进度与耗时规则

- 没有子步骤的顶层步骤计 **1 项**；有子步骤的顶层步骤按每个子步骤计数，父步骤不重复计入。
- 例如 3 个顶层步骤，其中 1 个有 3 个子步骤：总计 **5 项**；逐个完成这些子步骤显示 20%、40%、60%。
- 勾选 / 取消父步骤会同步全部子步骤；全部子步骤完成，父步骤自动完成。
- 耗时只累计 `running` 状态。**未暂停就关闭应用，重新打开后仍会累计关闭期间的时间**；需要停止计时请先暂停。
- 点击进度会立即保存；执行备注有约 600 ms 的防抖保存。保存失败保留输入并提示重试，不把失败操作当作成功。

### 快捷键

| 快捷键 | 作用 |
| --- | --- |
| `Ctrl+N` | 新建模板 |
| `Ctrl+F` | 聚焦首页搜索；编辑弹窗有输入时不会悄悄丢弃 |
| `Ctrl+S` | 保存当前模板 / 待保存内容 |
| `Esc` | 关闭当前弹窗；有未保存编辑时先确认 |
| `Space` / `Enter` | 激活当前聚焦的步骤或卡片；输入框不拦截空格 |

## 数据位置、导入和恢复

业务数据保存于 Electron 的 `app.getPath('userData')`，不在项目目录中；不同启动方式可能使用不同目录。可以设置绝对路径环境变量 `SOP_DATA_DIR` 来指定业务数据目录，不改变 Chromium 缓存位置。

```powershell
$env:SOP_DATA_DIR = 'C:\SOPData'
npm start
```

目录内包括：

```text
sop-data.json          主数据
sop-data.json.tmp      保存过程中使用的临时文件
backups/              最近 3 份写入前数据备份
window-state.json     窗口尺寸、位置和最大化状态
```

- 导入先选择 JSON，检查数量摘要，再选择 **合并** 或 **替换**。合并时相同 ID 保留更新时间较新的内容；时间相同保留本地版本。历史按执行身份、终态和完成时间去重。
- 替换会覆盖当前模板、执行记录和历史；自动备份有限，重要数据请另做外部导出，不要把 3 份轮转备份当作长期归档。
- 主文件有效时优先使用主文件；主文件损坏时逐个尝试从新到旧的有效备份，并显示恢复提示。所有备份也不可读时以空数据启动并明确报错，不宣称恢复成功。
- 恢复不会在启动时自动覆盖损坏原件。确认恢复结果后保存，或先另行导出再排查文件。
- 不要让多个应用实例同时写同一数据目录；当前不提供跨进程写锁或多用户并发保证。

## 开发与验证

保持原生 HTML / CSS / JavaScript + Electron，无 React / Vue、数据库或新增运行时框架。

| 入口 | 职责 |
| --- | --- |
| [主进程](<main.js>) | 安全文件写入、备份恢复、原生导入导出对话框、窗口生命周期 |
| [preload](<preload.js>) | 最小 IPC 白名单，不透传文件系统或原始 IPC |
| [数据层](<core/data-store.js>) | 旧数据兼容、规范化、合并及保存调用 |
| [进度](<core/progress.js>) / [实例](<core/instance-service.js>) / [模板](<core/template-service.js>) / [工具](<core/utils.js>) | 可在 Node 和浏览器使用的纯逻辑 |
| [页面渲染](<render.js>) / [交互控制](<renderer.js>) | 页面展示、事件、草稿、保存队列 |

`npm test` 使用 Node 内置测试工具，无额外测试依赖：核心逻辑、真实旧版格式迁移、实际临时文件系统故障注入，以及轻量 DOM / IPC 控制器回归。**它们不是完整浏览器 E2E 测试。** 另有真实 Electron / 便携程序验收，范围与未验证项见 [验收报告](<docs/V1.1-VALIDATION-REPORT.md>)。

保留 `contextIsolation: true`、`nodeIntegration: false`；导入和保存均在主进程再次校验结构，用户文本进入 HTML 前转义。本次依赖审计仍有 **22 项漏洞（4 moderate / 17 high / 1 critical）**，包括 Electron 与构建链，未用强制升级绕过兼容性验证；详见验收报告中的发布前风险。
