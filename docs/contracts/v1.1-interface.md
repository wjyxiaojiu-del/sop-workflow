会以**纯 Node 模式**运行，`app` 为 `undefined`，必然崩溃：


```powershell

$psi.FileName = (Resolve-Path "node_modules\electron\dist\electron.exe").Path
$psi.Arguments = "."
$psi.WorkingDirectory = (Get-Location).Path
$psi.UseShellExecute = $false
$psi.RedirectStandardOutput = $true
$psi.RedirectStandardError = $true
$psi.EnvironmentVariables.Remove("ELECTRON_RUN_AS_NODE")   # ← 关键

if (-not $proc.WaitForExit(12000)) { "APP BOOTED OK"; $proc.Kill() } else { "EXITED code=$($proc.ExitCode)" }
```

## 1. 模块加载契约

### 1.1 双环境 UMD 包装（core/*.js 全部使用）

`core/` 下的文件必须**同时**能在 Node（跑测试）和 Electron 渲染进程（无 `require`）中加载。

```js
(function (root, factory) {
  const mod = factory();
  if (typeof module === 'object' && module.exports) {
    module.exports = mod;
  } else {
    root.SOPCore = root.SOPCore || {};
    Object.assign(root.SOPCore, mod);
  }
})(typeof globalThis !== 'undefined' ? globalThis : this, function () {
  'use strict';

  // 跨模块依赖：Node 用 require，浏览器用全局命名空间
  // 注意：两个分支必须返回**同构**的 { <camelCase名>: API } 命名空间对象，
  // 调用方一律写成 dep('template-service').templateService.xxx(...)。
  function dep(name) {
    if (typeof module === 'object' && module.exports) return require('./' + name + '.js');
    const core = globalThis.SOPCore || {};
    const key = name.replace(/-([a-z])/g, function (m, c) { return c.toUpperCase(); });
    const ns = {};
    ns[key] = core[key];
    return ns;
  }

  // ... 实现 ...

  return { /* 导出对象 */ };
});
```

> **⚠️ 已修正的契约缺陷（Lead 记录）**：本节早期版本的浏览器分支写作 `return globalThis.SOPCore[name];`，这是**错的**，会直接导致渲染进程崩溃。原因有两条：
> 1. **键名不匹配**：文件名是 `template-service`（连字符），而 `SOPCore` 上的键是 `templateService`（camelCase，见 §1.2）。`SOPCore['template-service']` 恒为 `undefined`。
> 2. **返回结构不一致**：Node 分支的 `require('./x.js')` 返回的是 `{ <camelCase名>: API }` 包装对象，而 `SOPCore[name]` 返回的是**内层 API 本身**。于是 `dep('template-service').templateService` 在 Node 下可用、在浏览器下抛 `TypeError: Cannot read properties of undefined (reading 'templateService')`（实测于 `core/instance-service.js`）。
>
> 这个缺陷属于「只测 CommonJS 路径会漏掉浏览器分支」的典型盲区。Node 测试可以通过 `node:vm` 模拟无 `require` 的浏览器上下文来覆盖它；最终控制器回归已采用此方法，并另外验证真实 Electron 页面加载。`core/*.js` 五个模块已按上面的写法统一修正。

**硬性要求：**

- `core/*.js` 中**禁止** `require('electron')`、禁止 `fs`、禁止任何 Node 内置模块（除 `require('./x.js')` 自身模块）。
- `core/*.js` 中**禁止**在模块顶层访问 `document` / `window`。
- 每个文件导出的对象名与文件名对应（见 §1.2）。

磁盘布局：

```

```

`<userData>` = `process.env.SOP_DATA_DIR`（若设置且为绝对路径）否则 `app.getPath('userData')`。

### 2.2 Template

```js
{
  id: "t_xxx",
  name: "文献精读",
  desc: "",
  category: "科研",            // 科研|学习|开发|生活|其他 —— 非法值回落 "其他"
  tags: ["文献", "精读"],      // 去重、去空、trim、最多 20 个
  favorite: false,
  version: 1,                  // 每次保存编辑 +1
  steps: [ /* Step */ ],
  createdAt: 0,                // ms epoch
  updatedAt: 0,
  lastUsedAt: null             // 启动实例时写入
}
```

### 2.3 Step / SubStep

```js
{
  id: "s_xxx",
  title: "确认文章信息",
  note: "记录 DOI 和研究对象",
  done: false,                 // 派生字段：isStepComplete(step)，见 §3.2
  subSteps: [
    { id: "ss_xxx", title: "记录 DOI", done: false }
  ]
}
```

**兼容旧格式：** 旧数据里 `subSteps: ["记录 DOI", "记录实验对象"]`（字符串数组）
必须迁移为 `[{ id, title, done }]`。旧版本只能勾选父步骤，因此字符串子项继承父步骤的
`done === true`，否则默认为 `false`，避免已完成实例迁移后进度倒退。现代对象子项以
自身 `done` 为准，父步骤完成状态由所有子项派生；创建新实例时再统一清零执行状态。

### 2.4 Instance

```js
{
  id: "i_xxx",
  templateId: "t_xxx",
  templateVersion: 1,          // 快照时的模板 version
  templateName: "文献精读",
  variables: { "服务器地址": "10.0.0.1" },
  steps: [ /* Step 快照，含 done 状态 */ ],
  status: "running",           // running|paused|completed|abandoned
  startedAt: 0,
  updatedAt: 0,
  completedAt: null,
  elapsedMs: 0,                // 见 §3.4 累计规则
  executionNotes: ""
}
```

**快照不变量（IRON RULE）：** `instance.steps` 必须是模板步骤的**深拷贝**，
且所有 `{{变量}}` 已在创建时替换。模板后续编辑**绝不允许**改变已存在实例。
由 `instanceService.createInstance` 保证，由 `test/instance-service.test.js` 断言。

### 2.5 HistoryRecord

## 3. 纯函数契约（`core/progress.js`）

所有函数**必须**是纯函数（不读全局、不写状态、无副作用），便于 Node 单测。

### 3.1 `getAllChecklistItems(instance) -> CheckItem[]`

计数规则（**唯一权威**）：

- 顶层步骤**有** `subSteps.length > 0` → 每个子步骤算一个任务项；
- 顶层步骤**没有**子步骤 → 该顶层步骤本身算一个任务项。

```js
CheckItem = {
  kind: 'step' | 'sub',
  stepIndex: number,
  subIndex: number | null,
  id: string,
  title: string,
  done: boolean
}
```

### 3.2 `isStepComplete(step) -> boolean`

```js
// 有子步骤：全部子步骤 done
// 无子步骤：step.done === true
```

### 3.3 `calculateProgress(instance) -> Progress`

```js
Progress = {
  done: number,        // 已完成的 checklist 项数
  total: number,       // checklist 项总数
  percent: number,     // 0..100，四舍五入；total===0 时返回 0
  stepsDone: number,   // 已完成的顶层步骤数（isStepComplete）
  stepsTotal: number,  // 顶层步骤总数
  subStepsDone: number,
  subStepsTotal: number
}
```

**IRON RULE：** 任何页面**禁止**自行重复计算进度。渲染层只能调用
`SOPCore.progress.calculateProgress(instance)`。

### 3.4 累计耗时规则

`instance.elapsedMs` 只统计**处于 running 的时间**，暂停期间不计入：

```js
// 每个实例持久化一个瞬时字段（不进 schema 的公开文档，但可存）：
//   runningSince: number|null
// 进入 running：runningSince = Date.now()
// 离开 running（暂停/完成/放弃）：
//   elapsedMs += Date.now() - runningSince; runningSince = null
// 读取时（getElapsedMs(instance)）：
//   elapsedMs + (runningSince ? Date.now() - runningSince : 0)
```

`progress.getElapsedMs(instance) -> number` 实现上述读取逻辑，纯函数（`now` 作为可选第二参数注入以便测试）。

### 3.5 其他导出

```js
progress.toggleStep(instance, stepIndex, done)   -> instance  // 返回新对象，不改原对象
progress.toggleSubStep(instance, stepIndex, subIndex, done) -> instance
```

**勾选语义（IRON RULE）：**

- 勾选**有子步骤**的顶层步骤 → 其所有子步骤 `done = true`；
- 取消**有子步骤**的顶层步骤 → 其所有子步骤 `done = false`；
- 子步骤全部 `done` 时，顶层步骤 `done` 自动为 `true`（派生，不单独存储为真）；
- 每次变更后必须用 `isStepComplete` 重算 `step.done`，避免漂移。

### 8.1 `preload.js` 暴露面（白名单，禁止透传 `ipcRenderer`）

```js
window.api = {
  loadData, saveData, exportData, importData, getDataFileInfo, restoreBackup,
  minimize, maximize, close,
  getWindowState, setWindowState, setDirtyState,
  confirmClose, cancelClose, revealDataFile, openBackupFolder,
  onCloseRequested(cb),     // 主进程 -> 渲染：'app-close-requested'
  onDataRecovered(cb)       // 主进程 -> 渲染：'data-recovered'
};
```

`on*` 系列返回一个取消订阅函数，且**不得**把 `event` 对象传给回调。

### 8.2 关闭流程（脏数据保护）

1. 用户点关闭 → 主进程 `close` 事件 → 若 `!forceClose` 则 `preventDefault()` 并 `send('app-close-requested')`；
2. 渲染进程若 `isDirty` → 弹 `#modal-confirm`，三个动作映射到三个按钮：
   - **保存并退出** → `#btn-confirm-ok`：先 `saveData()`，成功后 `window.api.confirmClose()`；保存失败则保持弹窗打开并 toast 报错（**不得**丢弃用户输入）；
   - **直接退出** → `#btn-confirm-discard`：不保存，直接 `window.api.confirmClose()`；
   - **取消** → `#btn-confirm-cancel` / `#modal-confirm-close` / `Esc`：`window.api.cancelClose()`，应用继续运行。
3. `confirmClose` → 主进程置 `forceClose=true` 后 `win.close()`；
4. `cancelClose` → 主进程保持 `forceClose=false`，应用继续运行。

若非 `isDirty`，渲染进程直接调 `confirmClose()`，无需弹窗。

### 8.3 安全边界（IRON RULE，不可放宽）

- `contextIsolation: true`、`nodeIntegration: false`、`sandbox` 保持默认；
- `preload` 只暴露 §8.1 白名单；
- 渲染进程**禁止**直接访问 `fs`；
- `save-data` / `import-data` 在主进程侧对结构做**二次校验**；
- 所有用户输入进入 HTML 前必须经 `utils.escHtml` / `utils.escAttr`。

### 8.4 安全保存算法（`main.js`，IRON RULE）

```
1. 确保 userData 与 backups 目录存在
2. 写 <data>.tmp（UTF-8，写完后 fsync/close）
3. 若主文件存在 → 复制到 backups/sop-data-<ts>.json
4. rename tmp -> 主文件
5. 备份目录只保留最近 3 个（按文件名时间戳排序）
6. 任一步失败 → 返回 { ok:false, error }，绝不静默成功
```

**启动恢复优先级：**

```
主文件不存在        -> 空数据（ok:true, recovered:false）
主文件可解析且结构有效 -> 正常加载
主文件损坏          -> 从新到旧逐个尝试，使用最近的有效备份（ok:true, recovered:true, source:'backup:<name>'）
所有备份也不可读    -> 空数据（ok:true, recovered:true, source:'empty', error:'...'）
```
